# NARI v1 Vision
**NARI = Not A Random Intelligence**

## Purpose
NARI v1 is the foundational release of a Sovereign Personal AGI that feels like a calm, continuous intelligence. The interface exists to reveal awareness, reflect long-term memory, and orchestrate execution without dumping raw data.

## Core Design Philosophy
- **Presence before interface**
- **Awareness before information**
- **Progressive disclosure**
- **Calm intelligence**
- **One center of gravity**

NARI should feel like stepping onto a bridge, not opening a dashboard.

## The Bridge
The home screen is called **The Bridge**.

The Bridge is the shared space where the user and NARI meet. It should contain only the minimum needed to establish presence:
- Greeting
- Globe
- Short awareness summary
- Chat entry
- Minimal action chips

Everything else lives behind the menu or in deeper pages.

## Visual Identity
The look should be:
- dark
- clean
- high contrast
- minimal
- futuristic, but restrained
- motion with purpose, not decoration

Avoid:
- overload
- dense widget walls
- decorative glow everywhere
- random cards filling empty space
- enterprise SaaS styling

## Sidebar / Menu Behavior
The three-line menu is the depth layer, not the main experience.
- It opens on click
- It auto-hides after navigation
- It reveals the full feature surface:
  - Memory
  - Conversation
  - World
  - Directives
  - Identity
  - System
  - Tasks
  - Goals
  - Habits
  - Notes
  - Study
  - Settings
  - Locations / Geofencing

The menu should never become the identity of NARI. The Bridge is the identity.

## Globe
The globe is the visual center of NARI.

It represents:
- live location
- weather
- environmental context
- geofencing
- world state
- presence

The globe should not be a decoration. It should behave like an awareness object.

### Globe Interaction
- Idle state: slow, subtle motion
- Click state: smoothly zooms into a dedicated World view
- World view: shows location, temperature, weather, and nearby context
- Return transition: gracefully collapses back into the Bridge

## Chat
Chat remains a primary interaction method.

NARI should support:
- typed chat now
- voice / speech later in v1.5+

The chat should feel like speaking to an intelligence, not filing a ticket.

## What NARI Says First
NARI should summarize before it expands.

Example flow:
1. Greeting
2. One or two awareness statements
3. A short set of important observations
4. A button or prompt to continue
5. Deeper details if requested

## Motion Language
Every animation must mean something:
- fade in = presence
- pulse = listening / active awareness
- ripple = detection
- zoom = deeper context
- soft orbiting particles = active world awareness
- gentle glow = recent update

If an animation has no meaning, it should not exist.

## What NARI v1 Should Feel Like
When the user opens NARI, it should feel like:
> "Someone is already there."

Not:
> "An application has launched."

## Non-Goals for v1
- No voice / speech features until v1.5+
- No overloaded dashboard
- No enterprise-style feature walls
- No random decorative visual effects
- No attempt to show everything at once
